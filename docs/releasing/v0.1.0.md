# OXC for TSRX 0.1.0

> Draft release notes for the reviewed 0.1.0 candidate. Do not describe these
> artifacts as published until the registry, Marketplace, site, and social
> approvals in the launch runbook have each been granted and verified.

OXC for TSRX brings native Oxlint and Oxfmt behavior to `.tsrx`. Each release
pins a qualified canonical OXC revision; future revisions are adopted
deliberately behind one narrow Rust adapter. It is a companion integration,
not a fork, and the npm, Vite+, and editor layers stay thin.

## Included

- `oxlint-tsrx`, an Oxlint-compatible command that owns `.tsrx` and delegates
  ordinary `.js`, `.jsx`, `.ts`, and `.tsx` to the pinned official Oxlint
  package;
- `oxfmt-tsrx`, an Oxfmt-compatible command and API with check, write, stdin,
  config, and mixed-project behavior;
- project-local package resolution for the Vite+ lint and format commands;
- type-aware linting as an explicit `oxlint-tsgolint` opt-in;
- a thin VS Code document-selector client backed by the shared native language
  server, providing live diagnostics, validated fixes, and format-on-save; and
- release manifests and hosted build lanes for eight 64-bit native npm targets
  and eight matching platform VSIX artifacts.

Diagnostics and fixes use authored TSRX byte spans. Formatting is accepted only
after the result rescans and preserves the structural fingerprint before write.
Separately, the release gates reparse and prove one-pass convergence across the
179-file parser-valid Markless corpus in a disposable copy without writing to
Markless.

## Performance contract

The release does not turn the TSRX hot path into JavaScript AST materialization.
The current retained same-machine evidence reports 262.09 MiB/s for native
scan/projection/parse, 129.45 MiB/s sequential formatting, 742.54 MiB/s batch
format-check, 3.22 ms cold lint p95, and 2.84 ms fresh editor
open-to-diagnostics p95.
These are dated measurements with frozen budgets, not universal machine-speed
promises. The exact raw reports are
[lint](../../benchmarks/native-lint/results-1784242044684.json),
[format](../../benchmarks/native-format/results-1784242059253.json),

## Known boundaries

- Stock `oxlint`, `oxfmt`, and the official OXC VS Code extension cannot load a
  `.tsrx` language front end at runtime today. Use the companion packages and
  thin selector extension. The editor bridge should be retired if upstream
  exposes compatible configurable selectors and server loading.
- Embedded `<style>` payload bytes are preserved but not formatted or
  validated. Enabling OXC CSS formatting at the pinned revision would violate
  the no-patch dependency contract.
- Type-aware rules launch the supported TypeScript-Go companion only when
  explicitly requested; the default syntax lane remains one native OXC parse.
- The public playground is a static preview. Interactive native execution is
  restricted to the localhost development server and is not deployed.
- Platform intent is the eight-target matrix in the launch manifest and hosted
  workflow. The host package and VSIX are built and executed locally; producing
  and validating all eight release candidates remains a required post-push
  hosted gate. No JavaScript or WebAssembly fallback silently replaces a
  missing native build.
