# OXC for TSRX 0.1.3

A patch release. It fixes one defect in the 0.1.2 JavaScript plugin lane where a
whole-file rule could disappear without saying anything, and it makes every
remaining dropped report visible.

## The fix: a whole-file rule no longer vanishes on `.tsrx`

0.1.2 shipped a mapping for plugin rules that report on the whole `Program`, and
that mapping only recognised the shape when the label began at byte zero. A
`Program` node starts *after* leading trivia, so a single leading comment, or
even a single blank line, defeated it:

```text
                        .tsrx    .tsx
no leading trivia          1       1
leading blank line         0       1
leading line comment       0       1
leading block comment      0       1
// @ts-nocheck             0       1
```

The rule fired on the ordinary file and produced nothing at all on the
byte-identical `.tsrx`, with exit code 0, an empty Problems panel and no message
anywhere. 0.1.2's release notes claimed the opposite, which made it worse: the
documentation guaranteed a behaviour the build did not have.

The whole-file shape is now recognised from the projection's own copied-byte
bounds rather than from a zero offset, and the report maps to the first authored
byte it covers through the end of your file. That means it lands at the same
line and column as the identical `.tsx` — `2:1` and `2:1` for every variant
above — instead of drifting to `1:1`.

Exact mapping is still tried first, so precise positions are never coarsened,
and a report that covers no authored byte at all is still dropped rather than
given an invented location.

## Dropped reports are now counted and reported

A plugin report that lands entirely on projection-only text has no authored
position, and putting a squiggle on bytes you did not write would be worse than
dropping it. It is still dropped, but it is no longer silent:

- `--format=json` carries `oxcTsrx.jsPluginProjection.unmapped`
- the CLI prints a note on stderr
- the language server publishes a `js-plugins-unmapped` warning

An exit code of 0 with an empty panel no longer means "a rule was quietly
skipped".

## Upgrading

Nothing to change. If you use JavaScript plugins on `.tsrx` and your files start
with a comment, a licence header, or a blank line, whole-file rules that were
silently missing will begin reporting.

## Known boundaries

Unchanged from 0.1.2, and the limitations page is the full list. Worth
repeating: `context.filename` inside a plugin is the projection mirror path
rather than your authored path, the lane parses each linted `.tsrx` file one
extra time, and Windows is published but the editor lane has not been exercised
there.
