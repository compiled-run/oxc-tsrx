# OXC for TSRX 0.3.0

A parser compatibility release. The TSRX parser now accepts the authored forms that Octane's 2,137-file corpus exposed as failures, and a statement now starts at a markup line even when the previous statement has no semicolon. Sources that follow a no-semicolon house style parse and format instead of failing with a lexer error.

## Octane corpus compatibility (#9, #10)

`oxc-tsrx@0.2.3` returned no `Program` for 39 of Octane's 2,137 tracked `.tsrx` files. Multiline JSX attribute values, TypeScript generic arrows ahead of markup, JSX shorthand attributes, raw `<script>` payloads, and lazy destructuring patterns each failed with their own diagnostic:

```text
$ npx --yes --package=oxc-tsrx@0.2.3 oxc-tsrx-lint multiline-string-attr.tsrx
{"diagnostics":[{... "unterminated quoted string"}]}
```

The scanner, projection overlay, and reconstruction passes now carry these forms explicitly and restore their exact spans after the single OXC parse. All 39 failures parse in 0.3.0, and reference-compatible namespace imports and parenthesized JSX sequence expressions no longer surface an extra TypeScript diagnostic. Contributed by Dominic Gannaway in #10.

## A markup line starts a statement (#8)

A semicolon-less statement followed by a markup line inside an `@{}` body failed to parse, and every CLI inherited the failure:

```text
$ npx --yes --package=oxc-tsrx@0.2.3 oxc-tsrx-fmt --check a-no-semi.tsrx
Checking formatting...
oxc-tsrx-fmt: a-no-semi.tsrx: unterminated regular expression literal starting at byte 78
```

The scanner stayed in expression continuation state across the newline and read the `/` of the closing tag as a regular expression. Octane's compiler treats the two forms as the same program, so the parser now starts a statement at a line-leading committed markup opening:

```text
$ npx --yes --package=oxc-tsrx@0.3.0 oxc-tsrx-fmt --check a-no-semi.tsrx
Checking formatting...
Format issues found in above 1 files.
```

Ordinary comparisons and TypeScript type parameter lists are unaffected. The related Oxfmt refusal on a trailing `@if` whose sibling statement has no semicolon (`formatted TSRX structure differs from the input`) has a separate cause and remains open in #8.

## Repository metadata points at the current org

`npm view oxc-tsrx repository` reported `markless-dev/oxc-tsrx`, which redirects. Published packages now carry `compiled-run/oxc-tsrx` directly, and the release and publish workflows run under the new org guard.
