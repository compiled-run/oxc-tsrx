# OXC for TSRX 1.0.0

A version promise, not a feature release. Nothing about linting, formatting or
parsing `.tsrx` changed since 0.1.4. What changed is how much of this project is
proven by a run rather than asserted in prose, and that is what 1.0.0 is for.

Read this before upgrading: from here on, any change to the parser surface, the
plugin surface or the provider protocol costs a major version. That is the whole
point of the number, and it is the one thing 0.1.x did not give you.

## Every published platform now has a tier, and every tier is backed by a run

0.1.x shipped eight platform packages and told you they worked. Some of them had
never been exercised on their own hardware.

| Tier | Platforms | What a run proves |
| --- | --- | --- |
| 1 | `linux-x64-gnu`, `win32-x64-msvc`, `darwin-arm64` | on every pull request, on that platform's own runner: a real lint, a real format, two live `--lsp` sessions, that platform's own `parser.node` loaded, and a clean install of that platform's npm package outside this repository |
| 2 | `darwin-x64`, `linux-arm64-gnu`, `win32-arm64-msvc` | the same lint, format and `--lsp` runs, but only when a release candidate is built by hand |
| 2, carved out | `linux-x64-musl`, `linux-arm64-musl` | cross-compiled on glibc and never executed on a musl system at all |
| 3 | none | every published target has something behind it |

`docs/reference/platform-support.md` is the published version of that table, and
it says which is which for all eight, including the musl carve-out, in those
words. `tests/site/platform-support-matrix.test.mjs` compares the page against
`packages/toolchain/dist/native-targets.js` on every documentation run, so adding
or dropping a target fails until the page is updated. Which tier a target sits in
stays a judgment call; that it appears at all is checked.

`darwin-arm64` moved from the maintainer's laptop to a hosted runner, which is
why it is Tier 1 rather than a claim.

The Windows lanes are the biggest single change here. The parser addon suites run
there now, the packed parser fixtures are rooted on the path Windows actually
reports instead of the one POSIX would, and an installer that lands on an
unsupported Windows host fails with a message that names the reason instead of a
resolver error.

## The release gate looks inside the packages

The old gate proved that nine tarballs were produced. It did not open them.

`scripts/check-publish-artifacts.mjs` now reads each packed manifest, the eight
`@oxc-tsrx/native-*` pins, `checksums.json` and the parser addon record, and
compares all of them against one workspace version. A dry run exercises the same
backstop the real publish uses, so a rehearsal that passes means something. The
rehearsal also no longer asks GitHub for a publishing token: the workflow that
only rehearses carries no `id-token: write`.

## The version cut is scripted

Cutting 0.1.4 by hand touched 31 files. `bumpp` on its own would have touched
four of them, because the rest of this repository's version surface is the eight
`optionalDependencies` pins in `oxc-tsrx`, two `dependencies["oxc-tsrx"]` pins,
`Cargo.toml`, the committed `packages/toolchain/dist/parser.js`, the parser addon
record, and a long tail of test files that install or assert a literal version.

`scripts/sync-version.mjs` owns that surface: 73 declared locations across 25
files. It is not a search and replace. Every location is declared with the exact
shape it expects and how many times that shape must occur, so a file that moved
or changed shape fails the run and gets named, rather than quietly not being
updated. `.github/workflows/manual-release.yml` runs it, and
`pnpm run test:release` is the backstop that reads the root manifest at runtime
and asserts every package manifest equals it.

Release notes come from `changelogen` plus `scripts/release-notes.mjs`, which
appends the commits `changelogen` drops. No commit in this repository uses
`feat:`, so vanilla `changelogen` emitted 59 entries out of 154 and hid every
headline change. The count of listed commits now equals the count of commits in
the range.

## The documentation site was rebuilt

The site gained an interactive layer, the long prose walls were broken into
labelled facts, and the benchmark page draws real charts instead of hand-rolled
SVG. Three things were fixed along the way that a reader would have noticed:

- The extension id badges failed WCAG contrast in both themes, because a `0.75`
  opacity composited a 3.77:1 grey. The theme toggle also animated the palette
  change on resting rules, which flashed dark text on a light background on every
  flip.
- The home page was over its 250 KiB transfer budget. The stylesheet is now split
  per page shell, so the home page loads 28 KiB of CSS instead of 70 KiB.
- That split renamed `assets/style.css`, which the previous deploy's HTML still
  links. An unsplit copy ships at the old path so a cached document, a
  back/forward entry or an open tab still renders. Nothing the build emits links
  it.

## Also

- Install commands in the docs use a dist-tag instead of a frozen version, and a
  test keeps any documented `oxc-tsrx@N.N.N` pin from going stale.
- A `vp` scaffold can hand you a pnpm store mismatch. The error now says so.
- The registry page describes the package as what it is rather than repeating the
  tagline.

## Two files still say 0.1.4, on purpose

`docs/terminal-transcripts.json` holds captured CLI output, and
`docs/acceptance/performance-report.json` records a measured benchmark run. Both
carry the version of the binary that produced them. Refreshing the transcripts
costs a full native build, and restamping the performance report would make it
claim that 1.0.0 was measured when 0.1.4 was. They are evidence, so they keep the
version they were taken at. Nothing installs from either one.

## Known boundaries

Unchanged from 0.1.4, and `docs/reference/limitations.md` is the full list:
`.tsrx` cannot be built or bundled by this package, reports on
projection-rewritten nodes are dropped and counted, `context.filename` is the
mirror path, each linted `.tsrx` file is parsed once more, and Vite+ 0.2.6 pins
an `oxlint-tsgolint` version this package refuses to run.

`@oxc-tsrx/tsrx-core-compat` is stamped 1.0.0 in this repository but is not
published in this release. `oxc-tsrx-vscode` is also stamped 1.0.0 and ships to
the VS Code Marketplace on its own schedule. The nine names in
`docs/releasing/v0.1.0-launch.json` are what goes to npm.
