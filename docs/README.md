# Docs site

Documentation content lives in the markdown files under `guide/`,
`integrations/`, `architecture/`, and `reference/` (plus `index.md` for the
home page). `goals/` is internal project state and is not part of the site.

The site is generated by a small vanilla-JavaScript toolchain — no framework:

- `site.config.mjs` — title, nav, sidebar order, home hero/features.
- `build.mjs` — static generator (marked + highlight.js at build time,
  MiniSearch index for client-side search). Output goes to `dist/`
  (gitignored).
- `assets/style.css`, `assets/app.js` — theme toggle, search dialog, mobile
  drawer, outline scroll spy, copy buttons, and Navigation-API SPA routing
  (focus-preserving; non-Chromium browsers fall back to normal navigation).
- `assets/fonts/` — self-hosted Space Grotesk (display) and Inter (body).
- `generate-assets.mjs` — deterministic generator for `assets/logo.svg`, the
  `assets/hero-rays.svg` band artwork, and the `assets/logos/` candidates
  shown on `/logos`.
- `tsrx.tmLanguage.json` — TSRX TextMate grammar (vendored from the
  octanejs/octane website), used by shiki at build time for real TSRX
  syntax highlighting in code blocks and the home-page panel.
- `serve.mjs` — minimal static server for the built site, plus the home-page
  demo API (`/api/lint`, `/api/format`, `/api/highlight`, `/api/health`)
  backed by the real `target/release/oxc-tsrx{,-fmt}` binaries. With the
  binaries built, the hero panel becomes an editable playground with live
  oxlint diagnostics (hover tooltips) and one-click oxfmt formatting; without
  them it stays a static example.
- `assets/playground.js` — the playground client, lazy-loaded by `app.js`
  only when the panel exists and the API reports the binaries.
- `highlight.mjs` — shared shiki setup used by both the build and the demo
  API.
- `verify.mjs` — Playwright end-to-end verification (walkthrough, search,
  theme, mobile, axe-core accessibility, performance) using system Chrome.

```sh
npm run docs:build            # markdown -> docs/dist
npm run docs:serve            # serve docs/dist (default port 4173; pass another as arg)
npm run docs:verify -- http://localhost:4173   # requires the server running
```

Adding a page: create the markdown file (optional `title`/`description`
frontmatter), add it to `sidebar` in `site.config.mjs`, and rebuild.

## Interactive features

- `benchmarks-data.mjs` — generates the benchmarks page tables and SVG charts
  at build time from the latest `benchmarks/*/results-*.json`, so the page
  cannot go stale.
- `playground.html` — full playground: rule severities (`-A`/`-W`/`-D`),
  Oxlint config via `--config`, opt-in `--type-aware`/`--type-check`, format
  shown as a reviewable diff, and shareable `#code=` URLs.
- `tools/projection-dump/` + `generate-projection.mjs` — standalone Rust
  helper (path-depends on `crates/tsrx_syntax`, not a workspace member) that
  dumps the real lint projection; feeds the tabbed projection explorer on the
  Linting page and the `/api/project` endpoint.
- `llms.txt` / `llms-full.txt`, per-page `.md` twins with a copy-as-Markdown
  button, and a footer badge showing the pinned OXC revision and latest
  report date (both read from the repo at build time).
